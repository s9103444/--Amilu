## 3. 功能需求與業務規則　🟡 90%

- 3.1 模組一｜門戶與身份驗證（註冊／登入、Google 補填、手機驗證、開通創作者模式）

- 3.3 模組三｜個人化管理（個人資料設定、刪除帳號、作品集管理、接案設定、自訂標籤、Amilu 燈、約稿管理）

- 3.6 核心交易規則 → [[amilu_討論總結]]「3.1 50/50 雙向確認、全額託管與終止合作機制」

## 5. 畫面設計（UI Flow）　🟡 80%

- 5.0 設計交付物與開發依據

  | 交付物 | 內容 | 位置 | 狀態 | 開發用途 |
  | --- | --- | --- | --- | --- |
  | Wireframe | 灰階中擬真畫面，涵蓋所有 MVP 流程與狀態 | Figma `ui flow` 頁 | ✅ 畫面已齊，⬜ 箭頭待串 | **畫面內容、狀態與跳轉的依據** |
  | 元件庫／設計規範 | 色票、字級、按鈕／標籤／輸入框／燈箱／卡片的狀態樣式 | Figma `Amilu組件庫` 頁 | ⬜ 待整理 | **視覺樣式的依據** |
  | Mockup | 套用品牌色與源泉圓體的高擬真稿，只做代表頁：首頁、作品燈箱、委託討論牆（3～5 頁） | Figma（頁面待建） | ⬜ 待做 | 其餘頁面依元件庫推導，不逐頁製作 |

  - 規則與流程以本 spec 為準；畫面與 spec 有衝突時，以 spec 為準並回頭修正 Figma。
  - ui flow 中部分新畫面暫用 Noto Sans TC（源泉圓體無法在外掛載入），做 mockup 時統一換回源泉圓體。

- 5.1 ui flow 畫面清單 → Figma `ui flow` 頁
- ⬜ 5.2 畫面之間的連接箭頭（每個 frame 至少一條進、一條出，結束頁除外）
- ⬜ 5.3 畫面清單表（frame 名稱 → 對應功能 → 進入點 → 離開點）
- ⬜ 5.4 RWD：手機、平板版面（目前只有桌機寬）；Grid 定案 → 總結「1.1 Figma Grid（暫定，未定案）」
- ⬜ 5.5 元件與設計規範（按鈕、標籤、輸入框、燈箱、卡片的狀態樣式） → Figma `Amilu組件庫` 頁
